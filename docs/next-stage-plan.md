# GitNest 下一阶段精简与交互调整计划

日期：2026-11-15  
代码基线：`4f1b2e0a`，首轮残留清理及 Git 2.56.1 推送兼容修复已完成。  
状态：已完成（批次 1–6 已按计划落地并合入本地 `main`，已完成全量测试、12 组 UI 探针与安装包生命周期验收）。本文记录下一轮变更范围、执行顺序和验收要求。

目标：减少低频操作入口和重复实现，保留审阅 AI 成果、提交同步、合并、恢复及任务清理的完整路径。

## 1. 已确认的功能取舍

| 对象 | 决定 | 实施后的行为 |
| --- | --- | --- |
| 贡献统计 | 保留 | 保留入口、作者及时间范围统计、图表和分支选择 |
| 在线头像 | 保留 | 保留在线获取、缓存、本地头像和现有头像设置 |
| Linux／macOS 支持 | 保留 | 保留平台后端、平台分支、终端资源和打包支持 |
| 提交模板 | 删除 | 删除自定义模板管理、模板套用、变量及正则模板引擎，以及 Git 模板文件的导入入口 |
| 普通变基 | 删除发起入口及专用实现 | 复杂历史整理交由外部工具；已有外部变基状态继续识别和提示 |
| 多分支／多提交同时合并 | 删除 | 通过现有单目标合并流程逐个任务预览和执行 |
| “假定未修改” | 删除新增标记入口 | 保留已有标记的列表、说明和解除能力 |
| LFS | 保留基础能力，收窄管理入口 | 基础内容查看继续可用；删除 prune 和锁管理，其余管理操作收进高级入口 |
| 切换分支后更新子模块 | 改为明确选择 | 默认只刷新状态；用户在切换流程中主动选择后才更新 |
| Issue 链接规则 | 保留并收进高级设置 | 继续读取已有规则和显示链接，规则编辑放入高级区域 |
| Amend | 保留并调整入口 | 以“补充到上一次提交”表达，放入更多操作，并区分未推送和已推送提交 |
| 压缩包导出 | 保留 | 继续导出选定版本的文件快照 |
| 图片预览 | 保留 | 保留常见图片及 DDS、TGA、TIFF、PSD 预览和对应解码依赖 |

提交模板删除后，手动输入说明、最近提交说明复用，以及 `feat`／`fix` 等约定式提交类型辅助器继续保留。用户已有的 Git `commit.template` 配置及其指向文件保持原样。

现有历史、差异、签名与认证、单目标合并、stash、撤回／撤销、恢复备份、分支保护、工作树清理和 GitNest 更新检查继续保留。

## 2. 执行批次

### 批次 1：清理剩余无调用实现

- 复核并删除无调用的 `Commands/Am.cs`、`Commands/Clean.cs` 和 `Models/CleanMode.cs`。
- 清理 `Commands/Worktree.cs` 中无调用的 `AddAsync`、`PruneAsync`、`RemoveAsync`；保留查询、锁定和解锁方法。
- 清理 `Commands/Submodule.cs` 中无调用的 `AddAsync`、`SetURLAsync`、`DeleteAsync`；保留仍供克隆等流程使用的更新方法。
- 每项删除前核对应用、测试、XAML、JSON 生成和动态调用；同步清理因此失去用途的导入、资源和辅助方法。
- 工作树删除及失效记录清理继续使用 `WorktreeDeletionService`。

验收：Release 构建通过；工作树查询、删除、失效记录清理，以及克隆时初始化子模块的实际行为保持正常。

### 批次 2：移除普通变基、多目标合并和新增“假定未修改”入口

- 移除分支树、提交历史、菜单及快捷操作中发起普通变基的入口，清理对应视图、ViewModel、命令和仅供变基预演使用的实现。
- 移除多选分支／提交时的多目标合并入口，清理 `MergeMultiple` 和仅供其使用的策略模型及资源。
- 单目标合并继续复用现有预检、确认快照、实际结果反馈和恢复流程。
- 保留外部变基、挑选提交、补丁应用及冲突状态的识别和写操作拦截；已有外部流程由外部工具继续完成。识别和显示状态时不得自动继续、中止或删除 Git 操作状态目录。
- 移除文件菜单中设置 `assume-unchanged` 的入口；保留已有标记的查询、列表和解除，说明解除后文件变化会重新参与检测。
- 清理废弃图标和中英词条时，先区分发起操作使用的资源与外部状态提示仍需使用的资源。

验收：菜单和键盘操作无法发起被移除的操作；单目标合并正常；已有标记可以解除。包含外部变基／冲突标记的真实仓库仍能打开并显示状态，读取前后状态文件和用户文件内容一致。

### 批次 3：完整删除提交模板功能

- 删除仓库设置中的模板列表、新增、编辑、删除及选中状态。
- 删除提交说明选择菜单中的自定义模板和 Git `commit.template` 导入项，保留最近提交说明及其清空操作。
- 清理 `Models/CommitTemplate.cs`、`Models/TemplateEngine.cs`、`WorkingCopy.ApplyCommitMessageTemplate`，以及配置绑定、序列化字段和专用资源。
- 模板引擎中的变量替换、截取和正则替换随功能一起删除。
- 处理包含旧 `CommitTemplates` 字段的 `gitnest.settings`：首次迁移写入前保留原设置备份，新版不再加载或执行模板；其他仓库设置继续读取和保存。
- Git `commit.template` 配置键、模板文件、已有提交说明和用户当前草稿保持原样。

主要入口：[提交说明工具栏](../src/Views/CommitMessageToolBox.axaml.cs)、[仓库配置](../src/ViewModels/RepositoryConfigure.cs)、[仓库设置模型](../src/Models/RepositorySettings.cs)。

验收：模板管理和套用入口全部移除；带旧模板字段的设置可迁移，其他字段保持正确；手动输入、最近说明复用、约定式提交类型辅助器、普通提交和“提交并推送”均正常。

### 批次 4：收窄 LFS 管理并调整子模块更新

LFS 的处理范围：

- 保留 LFS 指针识别、状态及内容展示、图片预览，以及必要的对象读取和获取能力。
- 保留显式安装／启用、跟踪规则、fetch、pull 和手动 push，将其集中到“高级 LFS 操作”入口。
- 删除 prune 清理，以及锁列表、加锁、解锁、强制解锁和批量锁管理入口；清理仅供这些功能使用的模型、视图、命令方法及序列化项。
- 普通提交和推送继续尊重仓库的 Git LFS hooks 与配置；不自动清理 LFS 对象、不修改既有跟踪规则，也不默认跳过 hooks。

子模块的处理范围：

- 切换分支后默认只查询并刷新子模块状态，不自动递归更新目录。
- 在切换流程中提供默认不勾选的“切换后更新子模块”；选择后先展示受影响路径及递归选项，执行前确认。
- 既有仓库设置迁移到新的显式选择方式，不把旧的默认自动更新行为直接沿用为用户授权。
- 克隆时用户选择初始化子模块的流程，以及已有子模块的识别、打开和版本比较继续保留。
- 更新失败时分别报告“主仓库切换成功”和“子模块更新失败”，并刷新实际状态。

验收：默认切换不改变子模块工作目录及其 HEAD；显式选择后更新到目标提交，失败反馈准确；LFS 仓库仍可查看内容，保留的高级操作可用，被移除的管理入口不可达。

### 批次 5：整理高级设置和 Amend 交互

- 将 Issue 规则编辑从日常配置主界面收进默认折叠的高级区域；保留已有规则的读取、匹配、链接展示，以及显式选择共享规则的行为。
- 不因移动入口改写已有规则、Git 配置或 `.issuetracker` 文件。
- 将 Amend 从普通提交选项行移入更多操作，使用“补充到上一次提交”名称。
- 执行前明确展示被补充的提交、暂存内容和提交说明；保留现有暂存快照复核、提交身份、签名和 hooks 行为。
- 未推送提交允许确认后补充；已知已推送的提交默认引导新建提交。用户明确选择改写时，复用已有远端预检、分支保护、恢复引用和显式 lease 流程。
- 远端状态尚未核实时明确提示并要求先获取／核对，不能把未知状态当作未推送；操作后重新读取本地和远端结果。
- 提交已经成功而推送失败时，沿用现有只重试推送的流程，不再次执行 Amend。

验收：高级区域折叠时配置主流程清晰；Issue 链接仍可点击；普通提交与 Amend 含义明确；未推送、已推送、未知远端状态、受保护分支及推送失败的处理各有真实 Git 回归覆盖。

### 批次 6：集中回归、文档和交付

- 对贡献统计、在线头像、压缩包导出、特殊图片预览做保留能力抽查，确认入口和实际行为正常。
- 更新裁剪检查和受影响的 UI 探针；根据最终结构调整断言，不为维持旧数量而保留空白页签。
- 核对中英词条一致，清理已无用途的图标、绑定和序列化项。
- 更新 [产品与技术设计](design.md)、[实施记录](implementation-log.md)、[发行记录](release-notes.md)、README 和 [测试说明](../tests/README.md)。依赖实际变化时同步更新清单、快照和第三方许可。
- 重新发布 Windows x64 程序和安装包，记录最终构建结果、检查数量和安装包 SHA-256。
- 完成验证后回收临时仓库、工具、文件及测试数据，恢复验证前的用户配置。
