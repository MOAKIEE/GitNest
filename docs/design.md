## 1. 产品目标与已确认需求

GitNest 是面向使用 AI Agent 编程的 Git 初学者的中文 Windows 桌面客户端，基于 SourceGit 精简改造。用户通过 GUI 检查 AI 的成果、选择提交、合并发布和清理任务，复杂 Git 操作继续交给外部 AI 或专业工具。

核心路径：找到任务工作目录 → 审阅累计变化和未提交修改 → 选择提交 → 合并／推送 → 清理工作树与分支。任务只是用户为分支或工作目录添加的本地别名，不引入独立的 AI 任务运行系统。

- 兼顾个人和多人协作仓库。
- 采用现代 Windows 桌面风格，支持浅色、深色及跟随系统主题。
- 本地和远程分支沿用 SourceGit 原有分组与分支树显示，提供独立删除入口；本地删除保留可选的关联远端联动删除。
- 支持提交、推送、拉取、分支管理、合并、历史与差异查看。
- 支持从分支末端撤回一次或连续多次提交，分别提供保留代码、回退代码两种方式。
- 已推送提交可撤回，通过改写指定远程分支历史实现。
- 增加状态摘要、暂存工作、丢弃未提交修改、忽略文件、首次引导和操作恢复入口。
- 提供“撤销改动，保留历史”，与改写历史的撤回分开。
- 自动读取仓库实际生效的 Git 配置，展示来源，方便修改常用配置。
- 保留工作树列表和删除能力，用于清理 AI 创建后遗留的关联工作树。
- 冲突只提示，不提供冲突编辑器、自动解决或 AI 接入。
- 交付 Windows 安装包；用户另外安装 Git，安装包不附带 Git。
- 复杂操作由用户使用外部 AI 或其他工具完成。

## 2. 底座选择与改造方式

采用 SourceGit（MIT 许可），沿用 C#、Avalonia 和 Git 命令执行基础。优先保留已有页面、ViewModel、状态解析和命令实现，以主题、文案、入口裁剪和必要的流程补强实现产品目标，不整体重写客户端。源码核对与复用清单见 [SourceGit 复用核对](sourcegit-reuse-audit.md)。另已评估 [OldCoffee/GitNest 同名项目](oldcoffee-gitnest-review.md)，仅参考局部刷新与验证方法，底座继续使用 SourceGit。

SourceGit 官方使用说明要求预先安装 Git 2.25.1 或更高版本，并在 Windows 使用官方 Git for Windows。GitNest 的实际最低 Git 版本在实现阶段根据所用命令与兼容测试确定，不直接照搬上游下限。

实施时先选定并记录上游稳定版本与完整提交哈希，建立可构建基线，再逐步裁剪。保留上游许可证、版权和第三方署名。构建前核查该版本的 .NET SDK、Avalonia 版本及 Windows 支持条件。

## 5. 日常操作流程

### 5.1 提交与推送

1. 查看已暂存／未暂存列表和差异，按文件暂存或取消暂存，输入提交说明。
2. 展示当前仓库、分支与文件数量；提交期间阻止本程序并发修改该仓库。
3. 提交内容以确认时的暂存区快照为准。部分暂存文件分别展示已暂存与剩余修改；点击“暂存整个文件”才将其全部当前内容加入暂存区，普通提交不自动覆盖 AI 已有的部分暂存选择。执行前若暂存区发生变化，停止并重新展示。使用结构化参数和可靠的路径传递方式处理中文、空格及特殊字符。
4. “提交并推送”按两个步骤展示结果。推送失败时明确显示“本地提交成功，推送失败”，重试只推送。
5. 推送使用明确远端及单个分支 refspec；不隐式推送其他分支或标签。
6. 没有上游时让用户选择远端及目标分支，确认后建立关联；不默认覆盖已有异名分支。

提交身份缺失时引导填写当前仓库身份。Git 身份和远端登录账号分别展示，不混为一个设置。

### 5.2 获取与拉取

获取只更新远端信息；远程列表标注最后获取时间，离线时标注缓存状态。通过成功获取后的上游关系计算同步数量。

拉取默认只接受快进更新。分支发生分叉时提示“本地与远端都有新提交”，可由用户进入明确的合并流程，或交给外部工具。程序不静默变基、不自动改写本地提交。

### 5.3 分支删除

本地分支菜单显示“删除本地分支”；远程分支菜单显示“删除远程分支”。本地删除保留 SourceGit 的联动能力，提供默认不勾选的“同时删除关联远程分支”。勾选后列出两个独立对象，按钮变为“删除本地及关联远程分支”。从远程列表删除时不联动本地。

- 本地：禁止直接删除当前分支及被其他工作树使用的分支；后者可进入明确的“先删除工作树，再删除分支”流程。常规删除走 Git 的已合并检查；不满足时展示原因和差异，再通过独立的“仍然删除”流程处理。
- 远程：获取最新状态，确认远端 URL、分支名和当前提交。使用显式预期哈希约束删除；分支在确认后变化则停止并刷新。
- 删除远端分支后，本地同名分支继续保留，关联状态显示“上游已删除”。
- 不把删除远程跟踪缓存误当成删除服务器分支。
- 联动目标按实际 upstream 解析，不靠同名猜测。无上游时不提供联动；上游名称不同也展示实际映射，多个远端下不得误选。
- 联动前检查两侧的本地保护条件并获取远端 tip；先删除本地，再按显式 lease 删除远程。远程拒绝或变化时显示“本地已删除，远程未删除”，提供恢复本地分支入口，不自动重建远端。
- 本地删除前保存恢复引用，恢复同名分支前检查名称尚未被重新占用。远端重建必须作为新的显式推送操作。
- 确认页说明“删除分支不会删除已经合并到其他分支的提交”。

### 5.4 合并

页面用一句话表达方向：“将【来源】的改动合并到【目标】”。目标为本地分支；来源可以是本地分支或成功获取的远程分支快照。

执行前要求工作区和暂存区干净，预览来源、目标、将进入目标的提交及文件差异；重新核对两侧提交哈希后切换到目标。快进时直接前移，分叉时执行普通合并并生成必要的合并提交。成功后保留在目标分支，推送由用户单独操作。

冲突处理建议：本程序在干净工作区启动的合并发生冲突时，先核对操作记录、HEAD、合并标记、索引及相关工作文件状态；仅在确认仍为本程序刚产生的冲突状态且没有发现外部介入时尝试取消该次合并，取消成功后提示“合并存在冲突，已取消，目标分支未合并”。这避免只关掉提示后留下半完成状态。取消失败则显示真实状态并阻止继续写操作，不宣称已恢复。

打开仓库时已有外部合并、变基或冲突状态，只显示持续提示及冲突文件信息，待外部处理完成后刷新；不自动取消外部操作。

### 5.5 暂存当前工作

复用 `StashChanges`、`StashesPage`、`ApplyStash` 和 `Commands.Stash`，界面命名为“暂存工作／恢复工作”，与提交勾选区分。保存项显示名称、创建时间、来源分支及文件内容；兼容其他工具已创建的 stash。

保存前预览文件，默认包含未跟踪文件，不包含忽略文件。已有暂存区内容一并保存；恢复时可选择还原原有暂存状态，部分暂存内容仍按原状态展示。尚无首个提交时提示先创建初始提交。切换分支遇到未提交修改时，提供“暂存工作后切换”，不自动丢弃。

恢复前要求干净的工作区和暂存区，检查未跟踪及忽略文件覆盖风险。先 apply，成功后才按用户选择删除保存项；失败保留保存项。stash 没有与 merge 相同的 abort 命令，恢复冲突时提示“恢复未完成，保存项仍保留”，持续标记仓库待外部处理，不套用 merge abort 或直接 hard reset。首版不提供冲突解决器。

### 5.6 丢弃未提交修改

复用差异和丢弃确认界面，调整底层调用以明确基准：未暂存修改恢复到暂存区版本；“恢复文件到上次提交”同时影响该文件的暂存区和工作区。每个入口显示实际影响，不将两种操作混称为恢复。

按明确文件列表执行，不默认清理所有未跟踪或忽略文件。新建文件没有历史版本，提供独立的“移至回收站”操作；回收失败时保留原文件并报告失败。已跟踪文件被覆盖前保存可恢复的内容及所需索引状态到本地恢复存储，失败则停止丢弃；恢复前检查后续修改，避免覆盖新工作。该存储与仅能恢复提交的 Git 备份引用分开管理，默认保留 30 天。

### 5.7 忽略文件

复用 `AddToIgnore` 和 `GitIgnoreFile`，提供“忽略此文件／此类文件／此目录”预设及匹配预览。默认写项目 `.gitignore`，也可选择“仅本机”写 Git 的本地 exclude 文件。保留已有内容并避免重复规则，正确处理特殊字符、相对路径和已有反向规则。

已经被 Git 跟踪的文件不会因添加忽略规则停止跟踪；界面明确说明这一点，不附带删除索引中的文件。共享规则文件的变动显示在待提交列表，用户决定是否提交。

### 5.8 清理 AI 遗留工作树

保留 SourceGit 的工作树列表及 `RemoveWorktree` 弹窗，复用 `Commands.Worktree.ReadAllAsync`、`RemoveAsync` 和工作树刷新机制。入口命名为“工作树（独立工作目录）”，展示完整路径、分支或 detached HEAD、当前提交、锁定及目录存在状态。名称或路径不能可靠判断是否由 AI 创建，不据此自动清理。

删除前在目标工作树重新读取暂存、未暂存、未跟踪文件及忽略文件，分别显示数量和可展开列表；同时展示该分支相对上游的同步状态，没有上游或未获取时明确标注未知。用户应先停止仍在使用该目录的 AI 任务；程序只能检测自身操作及部分 Git 锁，不能保证发现所有外部写入。

- 主工作树不提供删除入口。当前正在 GitNest 打开的目标工作树需先关闭相应页面并切换到主仓库，再执行删除，命令工作目录不能位于待删除目录中。
- 默认“仅删除工作树目录”，保留本地和远程分支。确认页明确说明目录中的文件将被删除；`git worktree remove` 不经过 Windows 回收站。
- 存在未提交、未跟踪或忽略文件时默认停止，提示先暂存／提交或移走所需文件。忽略文件也可能随目录删除，不能把 Git status 干净等同于目录没有需保留内容。
- 保留独立的强制删除选项，用户主动选择后再次展示路径与将丢失的本地文件；涉及嵌套仓库或子模块时首版阻止强制删除，交由外部处理。
- detached HEAD 工作树删除前为其 HEAD 建立本地恢复引用，避免独有提交失去可见入口；该引用只能恢复提交，不能恢复未提交文件。
- 锁定工作树显示锁定原因，默认不删；用户确认目录可用且锁定已不再需要后，可复用解锁功能，再重新检查并删除。不能自动叠加 force 绕过锁。
- 可选“同时删除关联本地分支”，默认关闭；选中后可进一步选择删除其关联远程分支。分别展示目录、本地分支和远程分支，复用分支保护、预期 OID 和恢复检查。
- 执行顺序为工作树、本地分支、远程分支。每一步成功才继续，失败保留后续对象并报告已完成步骤；工作树已移除而分支删除失败时允许用户保留分支，不重新创建目录。
- 从本地分支删除入口选择“先删除关联工作树”时，走同一检查和执行流程，不另造一套删除逻辑。

删除必须使用 Git worktree 命令，并在执行前核对绝对路径、仓库归属和当前注册记录；不以递归删除目录替代。删除后重新读取工作树与分支列表。目录占用或 Git 拒绝时显示具体原因。

目录已被外部移走或删除时，提供“清理失效工作树记录”。先 dry-run 展示候选，再显式确认；说明 prune 可能清理多个过期记录，保留 Git 的过期与锁定规则，不把暂时离线的磁盘直接判定为遗留目录。

### 5.9 首次引导与历史文件

首次引导复用 Git 检测及仓库打开／克隆能力，依次处理缺失条件。已有有效提交身份直接读取并展示，不要求重复填写；区分提交身份与远端登录。

历史文件另存为后续直接开放上游已有入口，复用 `CommitDetail.SaveRevisionFileAsync`，不新建导出引擎；另存不改变当前分支或工作区，覆盖目标文件需确认。

### 5.10 AI 编程任务概览与快捷打开

在 SourceGit 原工作树区域补充信息，不另建工作树管理器。每项显示完整路径、可编辑别名、分支或 detached HEAD、已暂存／未暂存／未跟踪数量、相对上游的待推送／待拉取数量及刷新时间。别名与用户选定的比较目标保存在 GitNest 本机设置中，不修改分支名或写入仓库文件。

关联工作树自动从 Git 注册记录发现；AI 使用独立 clone 时需要作为另一个仓库打开，不仅凭相同远端地址就认定属于同一任务。用户可手动标记任务完成，工作区干净只表示没有未提交修改，不能显示为“任务已完成”。

提供“在资源管理器打开”“在编辑器打开”“在终端打开”和“复制完整路径”。优先复用上游入口和本机工具配置；以所选工作树为准确工作目录，工具缺失时提供选择路径。只打开工具，不自动启动 Agent、执行提示词或运行仓库脚本。

任务多时按需刷新并限制并行读取，避免每次文件变更扫描全部工作树。无上游、远端未获取、目录离线等情况独立显示，不以零或“已同步”代替未知。

### 5.11 审阅任务累计变化

复用上游历史、revision compare 和 diff 组件，提供“查看本任务改动”。用户明确选择比较目标，例如 `main` 或 `origin/main`，显示双方完整引用与快照哈希；可建议远端默认分支，但不能把当前分支的推送上游直接当成合并目标。

默认显示从双方共同祖先到任务 HEAD 的已提交变化，适合检查 AI 分多次提交后的整体成果；另提供“两分支当前版本差异”。两种比较分别标明基准，避免将目标分支独有的更新误算为 AI 修改。未提交变化单独展示，不暗中混入已提交比较。无共同祖先或存在多个共同祖先时说明比较条件，首版不自动挑选一个基准给出确定结论。

展示提交列表、文件数量、增删行统计和逐文件差异。二进制文件只显示适用的文件信息，不编造行数。比较为只读操作，不切换分支；比较期间分支变化使结果标记过期，刷新后再用于合并或删除确认。

### 5.12 任务完成后的清理

提供“清理任务”入口，将现有工作树、本地分支、关联远端分支删除流程集中呈现。用户逐项选择待清理对象，默认保留分支；勾选后显示完整路径与引用关系，复用第 5.3、5.8 节的检查和分步执行，不另建删除引擎。合并成功不自动触发清理。

删除前基于用户选择的目标分支，展示任务分支是否为目标的祖先，以及仅在任务侧可达的提交。若提交已进入目标历史，可显示“提交已合入所选目标”；否则显示“这些提交未出现在目标历史中”，并提供累计变化和两端差异入口。

压缩合并、变基或挑选提交可能改变哈希；缺少祖先关系不能直接断言代码未合并，两个版本相同也不能证明任务已测试或已经发布。程序呈现可验证的历史关系和代码差异，由用户决定是否清理。目标为远端分支时显示最后获取时间，获取失败不声称远端检查已通过。

## 6. 撤回与撤销提交的语义

### 6.1 两种模式

用户在历史中选择“回到此提交”，该提交保留，之后从当前分支移除的提交逐条列出。

| 模式 | 结果 | 实现方向 |
| --- | --- | --- |
| 撤回提交，保留代码 | 分支回到目标，当前文件内容保留为待提交修改 | `git reset --mixed <target>` |
| 回到此版本，丢弃之后的代码修改 | 分支与受版本控制的文件回到目标版本 | `git reset --hard <target>` |

首版只支持当前分支第一父链上的已有祖先目标，拒绝删除中间提交并自动重放后续提交。经过合并节点时，预览完整的可达性变化，不能只按界面上若干行计算影响。初始提交没有前一个版本，“撤回全部至空仓库”不提供入口。

执行前要求工作区和暂存区干净；存在本地修改时先提示用户处理，避免与撤回产生的修改混在一起。未跟踪及忽略文件也要检查路径覆盖风险，存在风险则停止；不附带执行 `git clean`。

### 6.2 已推送提交与多人协作

“不留下记录”定义为：从指定分支的可达历史中移除提交，不新增 revert 提交。其他分支、克隆、平台缓存和 Git 恢复记录可能仍持有原提交。因此产品按钮使用“改写远程分支历史”，不使用“彻底抹除”。

不能只看本地 ahead 数字就判断提交从未发布；状态必须说明相对哪个远端与分支，离线时显示远端状态未知。

执行流程：

1. 获取指定远端，确认本地 HEAD、目标祖先、远端当前 tip 与上游关系。
2. 远端 tip 必须处于本地可解释的历史内；存在未整合的远端提交或分叉则停止，让用户先同步。
3. 分别预览本地移除与远端移除的提交，以及代码保留／丢弃方式。若包含其他作者的提交，明确展示，不根据作者推断所有权或权限。
4. 将用户确认时的远端 tip 固定为预期值，执行前复核本地状态。
5. 创建本地恢复引用并记录操作阶段，然后执行本地 reset。
6. 使用 `--force-with-lease=refs/heads/<branch>:<expected-oid>` 和明确的单分支 refspec 更新远端。不能使用裸 `--force`，也不能依赖后台 fetch 会改变的隐式 lease。
7. 远端发生变化或拒绝强推时停止，显示“本地已撤回，远端未更新”及恢复入口；网络结果不明确时先查询远端再判断，不盲目重试。

lease 可防止覆盖确认之后的新推送，但无法判断别人是否已拉取旧历史。多人协作时仍应由用户协调历史改写。

建议默认将远端默认分支及 `main`、`master`、`develop` 列为本地保护对象，禁止常规删除和历史改写；用户可在仓库设置中明确解除本地保护。服务器保护规则始终有效；普通 Git 连接无法完整获取托管平台权限策略，实际拒绝信息需要准确呈现。

### 6.3 恢复与部分失败

撤回前建立 `refs/gitnest/backups/<operation-id>` 恢复引用，默认保留 30 天，只用于本地恢复，不列入普通分支或默认历史，不推送远端。恢复只覆盖已保存的提交状态，不宣称能恢复任意未提交文件。

操作日志保存仓库标识、分支、原 tip、目标 tip、预期远端 tip 和执行阶段。应用重启后检查未完成操作，并读取 Git 实际状态。恢复也需重新检查当前 HEAD、工作区及远端，不能自动覆盖后续新工作。

### 6.4 撤销改动，保留历史

复用 `Commands.Revert` 和对应页面，使用“撤销这次提交的改动（保留历史）”入口。预览待撤销提交和文件变化，在当前分支生成一条反向提交，随后按普通流程推送；共享分支优先展示此方式。

首版处理当前历史中的单次普通提交，合并提交的撤销需要选择主线并影响未来合并，交给外部工具，不静默沿用上游固定 `-m 1` 的策略。执行前要求工作区和暂存区干净。发生冲突时先按第 8 节核对操作归属与状态，条件满足才取消本程序发起的 revert，验证取消结果后提示；取消失败保持真实失败状态。提交钩子或签名失败需要单独识别，不能把页面关闭当成成功。

## 7. Git 安装、身份与认证

- 用户独立安装 Git for Windows，GitNest 安装包不捆绑、不自动下载或安装 Git。
- 首次启动搜索已安装 Git，执行版本检查；未找到时显示官方下载链接、“重新检测”和“选择 git.exe”。
- 设置显示实际使用的完整路径和版本，用户可更换；不修改全局 PATH。
- HTTPS 认证复用 Git Credential Manager 等已配置助手；SSH 复用现有 SSH 配置。
- GitNest 不保存明文密码或令牌，诊断内容隐藏凭据和 URL 内认证信息。
- 普通 Git URL 可用于不同托管平台；首版不依赖 GitHub 专有 API。
- 不主动覆盖用户全局 Git 配置。发布安装包前测试没有 Git、已有 Git、路径无效、版本不兼容及认证取消等情况。

### 7.1 自动读取工作区现有 Git 配置

“工作区”指用户打开的仓库或 Git worktree。打开子目录时由 Git 定位仓库；工作区文件夹中有多个仓库时逐仓库读取，不将配置混在一起。

复用 `Commands.Config` 和 `RepositoryConfigure`，在实际仓库目录下读取配置。通过 Git 解析系统、全局、仓库、本工作树以及 `include`／`includeIf`，不自行拼接 `.git/config` 路径或复制全局配置进仓库。结合 `--includes`、`--show-origin`、`--show-scope` 和机器可解析输出建立有序、多值记录，按具体配置项语义计算有效值。

上游字典模型需要扩展为包含键、原始多值、来源文件、作用域与展示值的数据结构；不能用最后一个字符串替代 `credential.helper` 等累积值。读取凭据相关内容时脱敏，不在日志中输出完整配置。Git 进程临时参数或环境覆盖可见时标记为运行时来源，不写回磁盘。

常用设置页展示：

| 配置 | 页面能力 |
| --- | --- |
| 提交姓名、邮箱 | 展示有效值和来源，修改当前仓库或显式选择全局 |
| 远端 | 显示远端名称、获取／推送 URL，编辑明确对象，保留其他 URL 与 refspec |
| 当前分支上游 | 选择远端及目标分支，展示实际对应关系 |
| 代理 | 读取并编辑常用 HTTP 代理项，URL 特定覆盖仍展示来源 |
| 签名 | 读取开关、格式和密钥标识，保留现有配置；依赖不满足时说明原因 |
| 换行处理 | 展示有效配置，放在高级设置中修改；不自动重新规范化已有文件 |
| 认证助手、SSH | 读取现有配置与来源，复用登录机制，不在普通设置中覆盖助手链或 SSH 配置文件 |

打开仓库、切换分支、切换工作树、应用重新获得焦点和保存后刷新配置，以反映 `includeIf` 以及外部修改；编辑尚未保存时发现变化，展示差异供用户重新确认。

### 7.2 配置编辑范围与保存

- 默认“当前仓库”：写 `--local`。界面说明同一仓库的多个工作树可能共享此配置。
- 已启用 `extensions.worktreeConfig` 时可选“当前工作树”：写 `--worktree`；未启用时不自动启用或迁移配置。
- 用户主动选择“此用户的全局配置”时才写 `--global`，保存前说明会影响其他使用该配置的仓库。系统、包含文件和运行时来源默认只读。
- 对继承配置，提供“为当前仓库覆盖”和“移除本层设置，使用继承值”；移除本层值、设置空字符串是不同操作。
- 保存只写变化的键，通过 Git 配置接口完成，不重写整个配置文件；保存前核对旧值，保留不相关键和多值设置。
- 保存后重新读取有效值及来源。更高优先级仍覆盖新值时说明原因；分项失败逐项展示，不能报告全部保存成功。
- 当前操作的显式策略与用户配置分开：例如首版拉取坚持快进模式时，应显示 GitNest 本次使用的策略，不悄悄改写 `pull.rebase`。

## 8. 实现结构与状态管理

建议分层：

1. 展示层：修改、历史、分支、确认弹窗、操作状态。
2. 用例层：提交并推送、定向合并、删除、撤回与恢复流程。
3. 策略层：干净工作区检查、远端预期值、分支保护、并发状态校验。
4. Git 适配层：命令参数、进程生命周期、输出解析和身份认证衔接。
5. 本地存储：设置、最近仓库、恢复引用元数据与脱敏操作记录。

同一仓库的本程序写操作串行化，并协调共享 Git common directory 的工作树。外部 AI 或 Git 工具可能并发修改仓库，执行前必须重新核对状态，遇到 Git 锁或状态变化停止并刷新，不删除锁文件。

### 8.1 外部 AI 操作与自动刷新

复用上游仓库刷新与文件监听机制，覆盖工作目录、索引、HEAD、引用、操作标记和配置；应用恢复焦点时补一次状态刷新，保留手动刷新入口。文件事件按仓库／工作树合并去抖，以代次标识取消或丢弃过期读取，旧请求结果不能覆盖新状态；按操作影响刷新状态、日志、stash 和工作树，避免无关仓库全量读取。监听须定位关联工作树的 gitdir 与 common directory，不能统一过滤 `.git` 或 `.gitignore` 而遗漏外部 Git 操作。监听只触发状态更新，不根据变化自动提交、合并或清理。

用户打开确认页时固定仓库身份、目标路径、HEAD、相关引用和操作涉及的索引／文件状态，执行前重新检查；变化时显示“仓库状态已变化，请重新查看”，原确认失效。提交内容依照暂存区，未暂存文件单独变化只刷新差异；丢弃等覆盖文件的操作则必须核对目标文件内容。

合并或 revert 自动取消仅适用于本程序发起、执行完成后尚未发现外部介入的同一操作。检查操作标记、预期 HEAD 和相关索引／文件状态；无法确认归属、发现新增修改或操作已由 AI 继续处理时，只提示并刷新，不自动 abort、reset 或恢复备份。文件监听和状态快照不是跨进程锁，无法消除检查后的竞争窗口；实施时应缩短窗口，使用 Git 原生锁，并在结果不明时停止后续写操作，让用户先暂停外部任务。

### 8.2 执行结果与命令边界

执行状态区分：准备、等待确认、执行、成功、失败、部分完成、结果待核实。取消或超时不等于操作未发生，重新读取本地和远端状态后才能报告结果。

文件及引用参数通过进程参数 API 传递，不拼接 shell 命令；引用名称先校验。保留 Git hooks 的正常行为，失败时显示原因，不默认跳过。

## 9. 安装与更新

首版目标为 Windows x64 安装包，Windows 10/11 作为拟定测试范围，最终支持版本以选定上游和依赖的验证结果为准。优先按用户安装，使用独立 GitNest 配置目录。

安装器方案在构建基线完成后确定。发布包包含应用运行依赖、许可证及必要资源，Git 由用户独立安装。首版采用手动下载升级；签名证书和发布渠道在发行阶段确定。卸载不删除用户仓库。

## 10. 实施阶段与验收

### 阶段一：构建基线

固定上游版本，完成 Windows 构建，记录依赖和许可清单；建立 GitNest 品牌和独立配置目录。

### 阶段二：核心页面

复用修改、历史、本地／远程分支树和 Git 检测，调整主题与文案；补充状态摘要、任务概览、累计差异入口、首次引导、配置来源和常用配置编辑；完成提交、获取、快进拉取、普通推送。

### 阶段三：操作流程

在现有分支与工作树删除（含可选联动）、合并、stash、discard、ignore、revert 和 reset 上补强确认与结果流程，实现任务清理编排、显式 lease、配置作用域写入、外部状态复核、恢复与部分失败状态。

### 阶段四：裁剪和安装交付

清理无用入口、代码和资源；完成安装、升级及高 DPI 检查，输出安装包。

界面测试覆盖点击与状态展示；实际 Git 集成测试检查磁盘中的引用、提交、索引和文件内容，不能只凭 mock 返回成功判定操作正确。

使用临时本地裸仓库及两个克隆模拟协作者，集成验证至少覆盖：

- 提交与已确认暂存区内容一致，部分暂存保留；文件级暂存／取消暂存不丢失工作区内容，提交成功但推送失败时不重复提交。
- 本地／远端独立删除入口正确，联动选项默认关闭；开启时核对真实 upstream，远端失败显示分步结果；拒绝直接删除当前或其他工作树占用的分支，显式工作树清理流程成功后才允许继续删除。
- 删除或改写确认后另一克隆推送新提交，操作被 lease 拒绝，协作者提交保留。
- 来源 A 合并到目标 B 的方向正确，A 不变；冲突后取消成功，B 恢复到合并前状态。
- 本程序不取消打开仓库前已有的外部冲突操作；AI 在本程序产生冲突后继续修改时，取消流程停止，不覆盖后续修改。
- 快进、分叉、没有上游、多个远端、远端分支已删除的状态正确。
- 撤回保留代码与丢弃代码的结果分别符合预览；根提交、合并节点和路径冲突处理明确。
- 远端拒绝、网络中断和应用重启后的部分完成状态可识别、可恢复。
- 后台 fetch 不改变已确认操作的 lease 预期值。
- 中文和特殊字符路径、二进制差异、空仓库、大量历史记录正常展示。
- 无 Git 时能引导独立安装，检测成功后继续使用；认证取消有明确反馈。

新增验收项：

- 工作树删除覆盖干净、脏目录、忽略文件、detached HEAD、锁定、主工作树、当前打开目录、目录占用和目录缺失。
- 仅删除工作树保留分支；联动删除按工作树→本地→远端执行，任一步失败准确呈现剩余对象；其他工作树及主仓库保持可用。
- detached HEAD 的提交可从恢复引用找回，失效记录清理预览与实际结果一致，离线／锁定目录不被误清理。

- 暂存工作包含预览的修改和未跟踪文件，恢复失败保存项保留；部分暂存、初始空仓库、跨分支恢复冲突和外部 stash 可正确处理。
- 丢弃操作准确区分暂存区与 HEAD 基准，恢复存储失败不覆盖文件，新文件回收失败不永久删除。
- 忽略规则对中文、特殊字符、目录和已跟踪文件的结果正确；仅本机规则不进入提交。
- revert 成功生成单条反向提交，原历史保留；冲突取消、钩子失败与签名失败状态准确。
- 配置读取覆盖全局继承、仓库覆盖、条件包含、多值助手、工作树配置和外部修改。
- 默认修改当前仓库，不改变全局；显式全局修改、恢复继承、空值及部分保存失败均有明确结果。
- 已有 Git 配置能直接使用，提交身份和远端认证不混淆；敏感配置值不出现在诊断记录中。

AI 编程流程验收：

- AI 已提交且工作区干净时，任务累计差异仍能展示；比较目标与推送上游不同的情况正确处理。
- 共同祖先比较与两端比较标注准确，压缩合并后不将未找到原哈希直接判定为代码未合并。
- 外部提交、暂存、切分支、变基和删除工作树后界面更新，失效确认不能继续执行，过期读取不能覆盖新状态。
- 工作树别名和快捷打开准确对应路径，带空格和中文路径正常；独立 clone 不被错误归入关联工作树。
- 清理仅执行用户勾选对象，步骤失败后保留未执行对象；合并／推送成功不自动删除任何对象。

## 11. 设计取舍

以下是为已确认需求提出的默认设计建议，后续可按实际使用调整：

- 本程序发起的冲突合并在归属与状态核验通过后尝试取消；外部 AI 已介入或状态不确定时只提示，不自动回滚。
- 首版拉取只快进，分叉由用户主动选择合并。
- 共享主要分支默认在本地保护，远端历史改写需展示确切影响范围。
- 本地恢复引用与丢弃前内容备份默认保留 30 天，不进入远端和普通提交历史。
- 首版聚焦文件级提交，不加入提交改名、压缩提交和中间历史改写。
