# GitNest 产品与技术设计

GitNest 是一款面向 AI 辅助编程工作流的跨平台 Git 桌面客户端，基于 [SourceGit](https://github.com/sourcegit-scm/sourcegit)（MIT）改造。用户可在图形界面中集中查看 AI 在各工作树中的累计成果与未提交改动，安全完成提交、同步、合并、回退与任务清理；复杂的底层历史整理仍可交由外部 AI 或命令行工具处理。

## 1. 产品定位与核心工作流

典型使用路径：

**定位任务工作树 → 审阅累计改动与未提交变更 → 选择提交与同步 → 合并并清理任务分支/工作树**

- **聚焦高频与高审阅场景**：重点强化任务工作树概览、累计差异对比、作用域配置管理与受控的危险操作确认。
- **与外部 AI 工具和平共存**：持续监听工作区及 Git 元数据变化；外部命令行进行中的 Rebase、Cherry-Pick、Bisect 或冲突状态仅只读提示并阻断冲突写入，不自动中止或覆盖外部流程。
- **不绑定独立 Agent 运行时**：工作树别名与比较目标保存在 GitNest 本机配置中，不修改分支名称或污染仓库文件。

## 2. 功能边界与安全机制

### 2.1 日常审阅与提交同步

- **工作树任务概览**：展示主仓库及所有关联工作树的本地别名、分支或 detached HEAD、暂存/未暂存/未跟踪数量、同步计数及刷新时间；支持直接打开所在目录、编辑器或终端。
- **累计差异审阅**：支持“共同祖先 → 任务 HEAD”和“两版本端点”两种比较基准；未提交修改单独列出；引用变化后自动提示快照过期并支持一键刷新。
- **文件级提交与独立 Amend**：保留部分暂存状态；提交与推送分步汇报，推送失败可仅重试推送而不重复提交。常规提交栏不放置行内 Amend，改为独立“补充到上一次提交”确认弹窗。
- **快进拉取与单分支推送**：拉取默认仅执行 `--ff-only`，分叉时引导通过合并流程处理；推送固定使用明确目标提交与 `--no-follow-tags`，避免隐式更新跟踪缓存或误推未选标签。

### 2.2 高风险操作防护

- **默认分支本地保护**：`main`、`master`、`develop` 及远端默认分支默认在本地禁止删除与历史改写（可在仓库设置中显式解除）。
- **单推地址与显式租约**：远端删除与历史改写均采用显式 `--force-with-lease=<ref>:<expected-oid>`，并在确认与执行前复核真实推送地址与目标引用（存在多推送地址时先阻断）。
- **本地恢复备份（默认 30 天）**：
  - 丢弃修改前为已跟踪文件备份原始内容及索引状态；未跟踪新建文件优先移入系统回收站。
  - 删除分支、删除 detached HEAD 工作树及重置/改写历史前自动建立 `refs/gitnest/backups/*` 本地恢复引用。
- **冲突归属与部分失败恢复**：仅由本程序发起且尚未发现外部介入的合并/`revert` 冲突会自动回滚现场；所有多步操作记录脱敏日志（隐藏 URL 凭据与认证头），异常中断或应用重启后可核对状态并恢复。

### 2.3 配置与裁剪范围

- **Scoped Git 配置**：使用 `git config --list --includes --show-origin --show-scope --null` 完整保留 `includeIf`、多值 `credential.helper` 与 URL 特定代理，按 Global / Local / Worktree 作用域显式编辑并检测外部变更。
- **精简界面入口**：首版移除内置 AI 提交生成、Custom Actions、Git-Flow、交互式变基、Cherry-Pick、Bisect、提交模板与内置冲突编辑器；保留贡献统计、在线头像、归档导出、基础 Git LFS 操作及常见/特殊图像预览，切换分支时对子模块更新采用默认关闭的显式按需确认。

## 3. 架构分层与平台支持

项目沿用 C#（`.NET 10`）与 Avalonia UI 跨平台框架，分层如下：

1. **展示层（`Views` / `ViewModels`）**：负责视图呈现、表单校验、确认快照与操作反馈，仅提供简体中文与英文及浅色/深色主题。
2. **用例与策略层（`Commands/*Service.cs`）**：实现仓库级写锁串行化、确认前状态快照复核、分支保护、显式 lease、冲突归属核对及操作日志恢复。
3. **Git 适配与平台层（`Commands` / `Native`）**：全部 Git 调用通过参数列表传递（无 shell 拼接），针对 Windows、macOS、Linux 提供各自的数据目录、钥匙串/凭据集成、系统回收站与进程分离支持。

## 4. 数据存储与更新机制

- **配置隔离**：默认存放于用户配置目录（Windows 为 `%APPDATA%/GitNest`，macOS/Linux 遵循平台标准目录）；若在可执行文件同级创建 `gitnest-data/` 目录，则自动切换为便携模式。
- **Git 依赖**：安装包不捆绑 Git，首次启动自动探测系统 Git（要求 `>= 2.31.0`）并在缺失时提供安装引导。
- **更新检查**：支持手动及启动时读取 GitHub Releases 最新正式版本（基于 SemVer 比较），发现新版本后引导前往项目发行页下载更新。
